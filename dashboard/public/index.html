    Problema de pesquisa

    Quando um post viraliza, o servidor da rede social aguenta? E qual jeito de construir esse servidor aguenta melhor?
    01

    Grafo

    A rede social vista como pontos (pessoas) ligados por linhas (quem segue quem). Poucas pessoas têm muitos seguidores.

    02

    Viralização

    Alguém compartilha, os seguidores veem e compartilham de novo. O post se espalha em ondas.

    03

    Medição

    Medimos quantos pedidos o servidor atende, quanto tempo demora e quantos dão erro.

    1 · A rede de teste

    Poucas pessoas concentram os seguidores

    Criamos uma rede com 10.020 pessoas, parecida com uma rede social de verdade. Metade das pessoas tem até 4 seguidores. Já as 20 “celebridades” têm de 2.150 a 5.000.

    3 · Os dois sistemas comparados

    Dois jeitos de salvar um post

    Os dois recebem os mesmos pedidos e usam o mesmo tamanho de computador. Muda a ordem das coisas: salvar antes de responder, ou responder antes de salvar.

    Síncrono

    Salva tudo, depois responde

    1. Cliente
    2. Nginx
    3. Laravel · PHP-FPM
    4. MySQLbanco de dados: salva o post no feed de cada seguidor

    Quando responde, está tudo salvo. Mas se o post tem muitos seguidores, a pessoa fica esperando.

    Com fila

    Responde na hora, salva depois

    1. Cliente
    2. Nginx
    3. Hyperf · Swoole
    4. RabbitMQfila: guarda o trabalho para depois
    5. Worker → Neo4jsalva aos poucos, em lotes

    A pessoa recebe “ok” rapidinho. O feed dos seguidores atualiza alguns segundos (ou minutos) depois.

    Conclusão

    Nenhum dos dois é melhor sempre. Depende de quem está postando.

    Pessoas comuns postando

    Pouca gente recebe cada post. O sistema síncrono, mais simples, dá conta.

    Celebridades viralizando

    Milhares recebem cada post. O sistema com fila segue funcionando, só que o feed demora um pouco para atualizar.

    Limitações
    • Tudo rodou num único computador, com recursos limitados.
    • Rede pequena e testes curtos (40 a 66 segundos).
    • Os dois sistemas dividem o processador de jeitos diferentes.
    • “Pronto” não quer dizer o mesmo nos dois: no síncrono já está salvo; no com fila, só foi recebido.
